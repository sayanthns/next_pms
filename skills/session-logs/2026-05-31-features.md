## Shipped (features 2, 3, 4 — APK deferred to its own cycle)

### 1. Fixed working-hours baseline — report consistency
- **Root cause of inconsistency:** three "hours" sources coexisted — PMS Checkin in/out (`office_hours`), PMS Time Log timer (`duration_hours`), task estimate fields.
- **Fix:** new `next_pms/api/_hours.py` = single source of truth. `compute_target_hours(user, from, to)` = effective working days × configurable `working_hours_per_day` (default 8, on PMS AI Settings). Excludes Sundays + holidays + **approved, non-cancelled** leave; **half-day leave = 0.5 day**. `compute_utilization(logged, target)`.
- `productivity.py` dropped its 4 duplicate helpers (imports them now), emits `target_hours` + `utilization_pct`. `ai_report.py _build_user_metrics` same. Checkin in/out retained as informational only.
- All `_hours` queries use `ignore_permissions=True` (PMS Manager role lacks HR-doctype read perms → would silently return empty otherwise).
- Tests: `next_pms/api/test_hours.py` (9 tests).

### 2. Mandatory budget
- `total_budget` required + **> 0 on NEW projects only** (`PMSProject.validate_budget`, `is_new()` guard → existing grandfathered). `reqd:1` on field + `CreateProjectModal.vue` required. Tests in `test_pms_project.py`.
- Frappe quirk: `reqd:1` treats `0` as present for Currency, so the controller `>0` check is the real enforcer.

### 3. Saturday weekly summary
- `send_weekly_summary` → cron `0 7 * * 6` (was generic `weekly`). Per active member (timer this week OR Active-project member; **System User only**) gets own email; configured `weekly_summary_recipient` (default sayanth@enfono.in) gets all-members table. Window **Mon 00:00 → Fri 23:59** (Saturday excluded — job runs Sat morning, would deflate utilization). Each `sendmail` wrapped in try/except + `log_error`.
