# Session Log — March 25, 2026

## Context
Continuation of Customer Portal Phase 2 & 3 implementation from previous sessions (Mar 17-18).

## Issues Discussed

### 1. Dashboard "Failed to load" on dev server
- **Cause:** Vite dev server (port 8081) can't proxy auth cookies to Frappe (port 8000)
- **Resolution:** Test via production build at `localhost:8000`, not the dev server
- **Decision:** Added `/assets` and `/files` proxy to vite.config.js, but auth issue remains inherent

### 2. Portal Analytics rendering full-page without sidebar
- **Cause:** Route was at top level, not inside the sidebar layout
- **Resolution:** Fixed by adding it to the router with proper layout

### 3. Current site set to `mysite.local` not `office`
- **Cause:** Local machine has `mysite.local`, production has `office`
- **Decision:** Documented in CLAUDE.md standing rules

### 4. Client Portal invite not working
- **Cause:** Project dropdown was loading ALL projects via `frappe.client.get_list` instead of portal-enabled ones
- **Resolution:** Created `get_portal_enabled_projects()` API, switched to `get_customer_users()` for role-based user selection

### 5. Task/ticket detail drawer stuck on "Loading..."
- **Root cause:** `get_portal_task_detail()` used `frappe.get_all("PMS Comment", fields=["content", "author"])` — WRONG field names
- **Fix:** Changed to `fields=["comment", "user", ...]` and added `ignore_permissions=True` to all queries
- **Lesson:** PMS Comment uses `comment`/`user` fields, NOT `content`/`author`

### 6. Portal access "Client portal is not enabled for project"
- **Root cause:** `invite_client()` auto-enabled portal AFTER `doc.insert()`, but the doctype's `validate()` checks it BEFORE insert
- **Fix:** Moved `frappe.db.set_value("PMS Project", project, "client_portal_enabled", 1)` to BEFORE the insert

### 7. No projects in Grant Access dropdown on production
- **Cause:** `get_portal_enabled_projects()` returns only projects with `client_portal_enabled=1`, but none were enabled on production
- **Resolution:** Changed flow: show ALL projects in dropdown, auto-enable portal when granting access

### 8. Customer accessing admin dashboard
- **Cause:** Missing route guard for PMS Customer users
- **Fix:** Added `router.beforeEach` check for `settingsStore.isCustomer` → redirects to `/portal`
