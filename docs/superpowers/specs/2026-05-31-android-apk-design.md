# Design — Next PMS Android APK (Capacitor, bundled)

**Date:** 2026-05-31
**App:** next_pms (Frappe v15 backend + Vue 3 SPA frontend)
**Scope:** Ship a sideloadable signed Android APK of the Next PMS SPA. Feature 1 from the 2026-05-31 batch (was deferred while features 2–4 shipped).
**Reference:** sibling project `fatehhr` (`/Users/sayanthns/Documents/fatehhr`) already does this exact thing (Capacitor + bundled Vue dist + token auth + signed APK). Model on it.

## Decisions (locked with user)

| Decision | Choice |
|----------|--------|
| Wrapper | **Capacitor** |
| Content | **Bundled** Vue dist inside APK (`webDir: ../frontend/dist`), offline shell; data from remote API |
| API target | `https://office.enfonoerp.com` (the live PMS site, served as `enfono-office-new`) |
| Auth | **API key/secret token** — login view → endpoint returns key/secret → Capacitor Preferences → `Authorization: token key:secret` |
| Signing | Reuse `fatehhr/android-capacitor/keystore/fatehhr-release.keystore`, sideload (no Play Store) |
| Push | Keep existing VAPID web push v1 (⚠️ reliability risk, see Risks) |
| appId / label | `com.eftpms.pms` / "Next PMS" |

## Why bundled (not remote-load)

Offline-capable, store-ready, no dependency on the SPA being reachable at page-load. Cost: the SPA today assumes same-origin + cookie session; bundled means a different origin (`https://localhost` Capacitor scheme) → **must** switch native requests to absolute URL + token auth. This is the bulk of the work and is gated strictly behind `isNative()` so the web build is untouched.

## Architecture

```
next_pms/frontend/                 # existing Vue SPA (web target unchanged)
  src/utils/frappe.js              # PATCH: API_BASE() prefix + native token header
  src/app/platform.js              # NEW: isNative(), API_BASE()
  src/views/NativeLogin.vue        # NEW: username/password, native-only
  src/store/auth.js (or similar)   # NEW/extend: store/clear token via Capacitor Preferences
next_pms/android-capacitor/        # NEW (mirror fatehhr)
  capacitor.config.ts              # appId com.eftpms.pms, webDir ../frontend/dist
  package.json                     # @capacitor/core, /cli, /android, /preferences
  android/                         # generated by `cap add android`
  keystore/                        # symlink/copy of fatehhr-release.keystore
next_pms/scripts/
  build-apk.sh                     # NEW: build → cap copy → assembleRelease → sign
next_pms/next_pms/api/auth.py      # NEW: get_api_credentials whitelisted endpoint
```

## Components

### 1. `platform.js` (frontend)
```
isNative()  -> Capacitor?.isNativePlatform?.() === true
API_BASE()  -> isNative() ? "https://office.enfonoerp.com" : ""
```
Domain is a build-time constant for v1 (single-tenant). (fatehhr parameterizes per customer; not needed here.)

### 2. `frappe.js` patch
- Every fetch URL becomes `API_BASE() + path`.
- `getHeaders()`: on web keep current cookie+CSRF behavior; in native mode, omit CSRF/cookie and add `Authorization: token <key>:<secret>` read from Preferences.
- `credentials: "include"` only on web. Native uses no cookies.

### 3. Native auth
- **`NativeLogin.vue`** — shown (router guard) only when `isNative()` and no stored token. Username + password fields.
- **Backend `next_pms.api.auth.get_api_credentials(usr, pwd)`** (whitelisted, `allow_guest=True` with justification: it IS the login):
  - Validate credentials via `frappe.auth.LoginManager` / `frappe.local.login_manager.authenticate(usr, pwd)`.
  - On success, ensure the User has `api_key`/`api_secret` (generate via `frappe.core.doctype.user.user.generate_keys` if missing), return them.
  - Throw on failure. Rate-limit consideration noted.
- Store returned key/secret in **Capacitor Preferences**; logout clears + returns to NativeLogin.

### 4. Backend CORS
- Allow the Capacitor origin so the bundled app (origin `https://localhost`) can call the API. Set `allow_cors` in the office site_config (or `allow_cors` via hooks) to include `https://localhost` (Capacitor android https scheme). Verify exact origin string on-device.

### 5. Build pipeline (`scripts/build-apk.sh`, copy fatehhr)
1. `cd frontend && yarn build` with a native flag (e.g. `VITE_BUILD_TARGET=native`) so `API_BASE()`/router default to native.
2. `cd ../android-capacitor && npx cap copy android` (+ `cap sync` first run).
3. `cd android && ./gradlew assembleRelease --no-daemon`.
4. Sign `app-release-unsigned.apk` with `fatehhr-release.keystore` (apksigner) → `next-pms-<version>.apk`.
5. Version from a `bump-version` step (reuse fatehhr `bump-version.mjs`).

### 6. First-time setup (one-off, document in README)
- `npm i -g @capacitor/cli` (or use npx), `cap add android`, install Android SDK/JDK 17, accept licenses. Reuse fatehhr `scripts/first-time-android.sh` as reference.

## Testing
- **Web regression:** `yarn build` (web target) + load `office.enfonoerp.com/next-pms/` — cookie login still works, no token path triggered (`isNative()` false). MUST be unchanged.
- **Native:** install APK on device/emulator → NativeLogin → enter creds → token stored → dashboard loads → at least one data API call succeeds via `Authorization: token`. Kill network → app shell still opens (bundled).
- **Auth endpoint:** unit test `get_api_credentials` — valid creds return key/secret, invalid throw, keys generated if absent.
- No automated APK/UI test (manual device verification).

## Risks
1. **Auth rework touches every API call.** Mitigate: all native branches behind `isNative()`; web path byte-for-byte unchanged; land the `frappe.js` patch with web regression test first.
2. **Web push from bundled `https://localhost` WebView is unreliable on Android** (background delivery often unsupported). v1 keeps web push; if it doesn't deliver on-device, v2 adds native FCM via `@capacitor/push-notifications`. Documented, not solved in v1.
3. **Local Android toolchain** (SDK, Gradle, JDK 17) must exist on this Mac. fatehhr builds locally so likely present — verify in the first plan task before building.
4. **CORS origin string** for Capacitor android https scheme must be confirmed on-device (`https://localhost` vs app origin); adjust site_config accordingly.
5. **Keystore reuse** — same signing identity as fatehhr; fine for sideload, different appId. Keystore password needed at build time (in fatehhr build script/env).

## Out of scope (v1)
- Google Play listing.
- Native FCM push (v2 if web push fails).
- iOS build.
- Per-customer/multi-tenant build parameterization (fatehhr has it; next_pms is single-site).
- Biometric unlock (fatehhr has it; defer).
